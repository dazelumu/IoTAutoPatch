# 0.3.1 CVE-2024-57595 wrapper 修复闭环与案例归档

日期：2026-10-25

## 范围

0.3.1 在 0.3.0 基础上补齐受限表单 POST/多步协议路线的真实模型修复闭环，新增 runtime sink differential probe 和 wrapper 修复模式，修复真实 run 暴露的定位与验证问题，并完成 CVE-2024-57595 团队案例归档。权威运行时与架构范围仍限于 `native-proot-mips32be` / `mips32be`。

## 变更

- 新增 runtime sink differential probe：确认命令注入 marker 后，对模型已发现的多个 redirectable command sink 执行受控差分探测；完整重放认证前缀和 marker 触发步骤，排除已证明未拦截的 site，回滚失败立即中断并保留为基础设施失败。
- 新增 wrapper 修复模式：模型只提供参数判定函数，控制器生成 trampoline；判定返回 0 时从原 GOT 项重新加载原 callee 并 tail-call，返回非零时直接回到原调用者，保留合法调用副作用。
- 加强定位与重定位：`function_calls` 分页响应携带 `next_offset`，过滤查询优先于宽泛分页，marker handler 覆盖门禁阻止模型只检查无关 handler；候选失败先在同 site 修正判定逻辑，预算耗尽时诚实报告而不是猜测。
- 修复 baseline 冗余重启：已 ready 的 baseline 直接复用；`target_start_failed` 只受控重试一次，警告脱敏保存；候选 pre-ready 崩溃仍保留为失败证据，不被重试掩盖。
- 修复离线 `repair verify` 对多步 fixed-check 的协议兼容问题：按 run config 中注册的协议校验，不再回退到默认 GET/HEAD 协议。
- 归档 CVE-2024-57595 团队案例：六步声明式 PoC、模型 proposal、`repair.c`、patch record、候选摘要、run 报告 JSON、独立验证 JSON 和脱敏摘要。
- 按成熟开源项目文档结构补充文档索引、贡献指南和安全策略；重写项目 README 与操作手册，使 README 回到入口/快速开始/能力摘要，配置、工作流、更新和排障细节进入 `docs/OPERATIONS.md`。
- 同步 README、路线图、架构说明、操作手册、变更记录、已验证固件清单和验证总账；`.gitignore` 放行 `cases/**/patches/*.json` 与 `cases/**/results/**/*.json`。

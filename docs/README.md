# 文档索引

本项目的文档分为四类：入门与操作、架构与证据、能力与路线、社区流程。读文档时以当前版本的能力边界为准，不要用历史成功 run 推断新固件支持。

## 推荐阅读顺序

1. [项目 README](../README.md)：定位、安装、最小工作流和当前能力；
2. [操作手册](OPERATIONS.md)：配置、路线 A、结果解释、更新和故障处理；
3. [架构说明](ARCHITECTURE.md)：控制器如何约束执行、证据、模型和验证；
4. [已验证固件清单](SUPPORTED_FIRMWARE.md)：真实闭环证据的唯一入口；
5. [路线图](ROADMAP.md)：通用化计划、阶段边界和完成标准；
6. [案例规范](../cases/README.md)：实验结束后如何归档可分享证据。

## 文档职责

| 文件 | 读者 | 维护规则 |
|---|---|---|
| `../README.md` | 新用户和维护者 | 只保留入口、快速开始、能力摘要和文档导航 |
| `OPERATIONS.md` | 操作者 | 必须给出可复制命令、配置语义和安全提示 |
| `ARCHITECTURE.md` | 开发者 | 说明模块边界、信任模型、数据流和扩展点 |
| `SUPPORTED_FIRMWARE.md` | 所有读者 | 只登记真实闭环组合；新增行必须满足入库标准 |
| `ROADMAP.md` | 维护者和合作方 | 区分已实现、已验证、规划和未验证 |
| `../cases/README.md` | 实验执行者 | 定义案例卡、PoC、补丁和脱敏结果的归档契约 |
| `CONTRIBUTING.md` | 贡献者 | 开发环境、测试策略、证据语言和 PR 检查单 |
| `SECURITY.md` | 所有用户和漏洞报告者 | 说明隔离边界、数据外发和报告流程 |
| `CHANGELOG.md` | 发布维护者 | 只保留面向使用者的版本变化 |
| `releases/<version>.md` | 发布复核者 | 记录版本范围、变更、检查和明确非目标 |
| `../VALIDATION.md` | 审计者 | 历史验证账本；保留旧证据和执行环境，不重写结论 |

## 写作规则

- 面向团队仓库写作，不写个人电脑路径、用户名、密钥或私有会话数据；
- 区分“已实现”“定向测试通过”“真实模型闭环”“独立 verify”和“未验证”；
- 命令使用 `<case.yaml>`、`/path/to/...`、`$CASE_WORK` 等可替换占位符；
- 配置示例必须可被当前 schema 接受；
- 成功声明必须绑定固件 SHA、目标 SHA、run ID、候选 SHA 和验证结果；
- 新固件没有进入支持矩阵前，不能在 README 中写成已支持；
- 版本发布后不改写历史结论；发现文档错误时新增勘误或新版本记录。
